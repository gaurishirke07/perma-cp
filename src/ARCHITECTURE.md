# Architecture — depth-conditional conformal pipeline

> One-page reference for `src/`. The paper's claim (a single *global* conformal calibration
> mis-covers permafrost borehole temperature in a *depth-structured* way; calibrating by depth
> and adapting to drift restores coverage) is realized by the flow below. Constants:
> **SEED=42, HORIZON=30 d, ALPHA=0.10 (nominal 90%)**, CPU-only. See `../README.md`,
> `../paper/RESULTS.md`.

## Pipeline flow

```
data/*.parquet ─► features.build_features ─► run_seed.time_split ─► LGBMRegressor ─► conformal.* ─► figures/*.png
  long table       per-(site,depth) daily     60/20/20 by DATE       quantile α=0.5    calibrators     results/*.csv
                   feature rows, target y      test = most recent     (median point     (coverage +
                   = temp_c at t+h             (warmest) window        forecaster)       width per depth)
```

`run_seed.py` is the canonical single-site pipeline and defines the shared constants and
`time_split`; every other driver imports those plus `features` and `conformal`, then loops the
same load → features → split → fit → calibrate → aggregate steps over more sites/methods.

## Data contract

Canonical **long table**, one row per (site, date, depth):

| column | type | meaning |
|---|---|---|
| `site_id` | str | PERMOS borehole id (e.g. `STO_6000`) |
| `date` | datetime | observation day |
| `depth_m` | float | sensor depth in metres |
| `temp_c` | float | ground temperature (°C) |

Three parquet files share this schema: `borehole_long.parquet` (pilot STO_6000),
`borehole_subset_long.parquet` (5 crest sites), `borehole_all_long.parquet` (25 sites, **plus a
`morphology`/landform column** used only by `run_all.py`). Source: PERMOS Database 2025,
DOI:10.13093/permos-2025-01, CC-BY 4.0.

## Modules

| module | role (one line) |
|---|---|
| `features.py` | `build_features()` — per-(site,depth) daily-reindexed feature table: lags 1/7/30/365 d, 30-d rolling mean/std, sin/cos day-of-year, `depth_m`, `year`, `time_idx`; target `y = temp_c` at t+h. Also `depth_band()` and `FEATURE_COLS`. |
| `conformal.py` | All calibrators + `conformal_quantile()` (Vovk finite-sample rank), `coverage_and_width()`, and the AR(1) diagnostic/whitening helpers. Pure functions over `cal`/`test` frames carrying `abs_resid`. |
| `run_seed.py` | Single-site pilot (STO_6000): global + Mondrian + AR(1)-whitened; per-band coverage + residual-autocorrelation diagnostic. Defines `time_split`, `SEED`, `ALPHA`, `HORIZON`, `NOMINAL` (imported everywhere). |
| `run_subset.py` | Same pipeline on 5 crest boreholes, per-site model — tests whether the global miss / Mondrian recovery **replicate**. |
| `run_all.py` | Full population (25 qualifying boreholes) + **landform (morphology) selection-bias check**; global vs Mondrian. |
| `run_adaptive.py` | **Method A** driver: global vs Mondrian vs Mondrian+ACI across 25 boreholes; coverage and width-cost figures. |
| `run_continuous.py` | **Method B** driver: Mondrian+ACI (A) vs depth-normalized (B) vs depth-normalized+ACI across 25 boreholes. |
| `stress_test.py` | Extreme-case coverage (all / warmest-10% / thaw-zone \|y\|≤0.5 °C / worst-site deep) + Winkler interval score; global vs Mondrian vs A. |
| `analyze_domain.py` | Per-band **point** RMSE/MAE across 25 boreholes vs published permafrost-ML anchors (base-forecaster credibility check). |
| `gate_checks.py` | One-off Gate 1/2 provenance script: granularity, missing%, deep-trend slope, variance-vs-depth; builds the canonical parquet. Run from the raw PERMOS `Data/` dir, not the repo root. |

## Depth bands

Mondrian calibration groups (from `features.depth_band`), chosen coarse enough to hold enough
calibration points per band:

| band | range | regime |
|---|---|---|
| `shallow(<1m)` | < 1 m | seasonal heteroscedasticity (high variance, high residual autocorrelation) |
| `mid(1-5m)` | 1–5 m | attenuating seasonal signal |
| `deep_seasonal(5-20m)` | 5–20 m | near the ~18 m zero-annual-amplitude level |
| `deep_trend(>=20m)` | ≥ 20 m | warming-trend drift (tiny variance, systematic cal→test bias) |

## Calibration variants

All wrap a point base forecaster with absolute-residual split conformal: half-width `Q =
quantile_{1-α}(|r_cal|)`, interval `= ŷ ± Q`. They differ in how `Q` is grouped and adapted:

| variant | function | one line |
|---|---|---|
| Global | `global_conformal` | One pooled `Q` over all depths — the baseline that mis-covers (under shallow, over deep). |
| Mondrian | `mondrian_conformal` | Per depth-band `Q_b` — fixes heteroscedastic shallow/mid, leaves deep-trend drift under-covered. |
| **Method A** — depth-adaptive | `mondrian_aci` | Mondrian bands **+ ACI** (Gibbs & Candès 2021) online drift adaptation *within each band* — restores every band incl. deep-trend at ~no width cost. |
| **Method B** — depth-normalized | `depth_normalized_conformal` | Continuous per-depth scale `s(depth)` = cal-residual std; one pooled quantile on normalized scores, rescaled per test depth (bin-free). Optional global ACI (`aci=True`) — but drift is depth-local, so global ACI over/under-corrects. |
| AR(1)-whitened | `mondrian_ar1_whitened` | Robustness check: per-band quantile on AR(1)-whitened cal residuals (after Berk 2025), rescaled to raw — shows the deep miss is **drift, not autocorrelation**. |

## Parameter contract: values, reasons, consistency

**Single source of truth (grep-verified across all 19 `src/*.py`, 2026-10-08):** every driver
imports `SEED`/`ALPHA`/`HORIZON`/`NOMINAL` from `run_seed.py` (the only file that defines them),
builds the forecaster via `model.make_base_model`, takes the ACI step `gamma=0.03` from
`conformal.py` defaults, and the depth bands from `features.depth_band`. No driver redefines any of
these. The robustness evals each vary **one** dimension and hold the rest to this contract, so every
baseline case reproduces the accepted-paper numbers exactly (confirmed per eval).

| Parameter | Value | Reason | Validated by |
|---|---|---|---|
| seed | 42 | fixed for reproducibility; the exact value is arbitrary (a fixed seed is the point) | B2: coverage seed-invariant (dev ±0.0035) |
| horizon h | 30 d | short operational window; calibration is *verifiable* at short horizons (a 30-d interval can be checked against what happens, a multi-year one cannot); multi-year warming enters as deep-band drift, not a long forecast | h=90 still holds (0.90/0.90/0.87/0.88) |
| alpha | 0.10 (90%) | standard decision-relevant interval level | reliability sweep 0.5-0.99 |
| split | 60/20/20 chronological, shared dates | must split by time so warming makes test non-exchangeable with cal (the premise); 60 train / 20 cal (enough for the 1-alpha order statistic) / 20 most-recent-warm test | — |
| bands | <1 / 1-5 / 5-20 / >=20 m | a-priori from permafrost thermal structure (active layer; ZAA ~18 m, Isaksen 2000); 1/5 m subdivide the seasonal zone; NOT clustered from the outcome (anti-circular) | B1: robust to edge choices |
| ACI gamma | 0.03 | small conservative online step: stable yet tracks the slow drift | B3: coverage flat for gamma 0.01-0.10 |
| score | \|y-yhat\| | standard split-conformal symmetric score around a point forecast | B6/CQR = asymmetric contrast |
| features (11) | lag 1/7/30/365, roll mean/std 30, sin/cos DOY, depth, year, day-idx | daily/weekly/monthly/annual memory + recent level/volatility + seasonality + the depth axis + two warming-trend terms; no exogenous drivers (small, portable, trust on calibration) | leakage test |
| gate | train>=500, cal>=200, test>=200 | minimum data for a stable fit, a finite-sample 90% calibration quantile, and a meaningful coverage estimate | — |
| LightGBM | 400 trees, lr 0.05, num_leaves 31, min_child_samples 40, subsample 0.8, colsample 0.8 | a single small, mildly-regularized, **untuned** config, frozen and identical everywhere (the claim is calibration, not accuracy) | B2/B5: result doesn't hinge on it |

**Correction flagged for the paper (App B.2):** the text "400 trees, learning rate 0.05, otherwise
library values" is inaccurate. `num_leaves=31` is the only true LightGBM default; `min_child_samples=40`
(default 20), `subsample=0.8` (default 1.0) and `colsample_bytree=0.8` (default 1.0) are **not**. The
honest camera-ready wording: "a single fixed, mildly-regularized, untuned configuration (400 trees,
lr 0.05, num_leaves 31, min_child_samples 40, subsample 0.8, colsample_bytree 0.8, seed 42)." None of
these were tuned against coverage; the forecaster is held fixed because the contribution is the
calibration layer.

## Reproduce

CPU-only; base forecaster is a quantile `LGBMRegressor` (`objective="quantile", alpha=0.5`,
400 trees, `random_state=SEED`), deliberately untuned (the claim is calibration, not accuracy).
Each entry point has a `main()` and reads `data/*.parquet`, writing its table(s) to `results/`
via an absolute repo-root path, so run from the repo root. Figures are drawn separately by
`make_figures.py` from those CSVs:

| command | produces |
|---|---|
| `python src/run_seed.py` | pilot: `results/coverage_{global,compare,ar1_whitened}.csv`, `per_band_coverage_summary.csv`, `residual_autocorr_by_band.csv` |
| `python src/run_subset.py` | `results/coverage_subset_*.csv` |
| `python src/run_all.py` | `results/coverage_all_*.csv` |
| `python src/run_adaptive.py` | Method A: `results/coverage_adaptive_bands.csv` |
| `python src/run_continuous.py` | Method B: `results/coverage_continuous.csv` |
| `python src/run_reliability.py` | `results/reliability_sweep.csv` |
| `python src/run_coverage_ci.py` | `results/coverage_ci.csv` (cross-site bootstrap CIs) |
| robustness drivers (`run_band_sensitivity.py`, `run_gamma_sweep.py`, `run_seed_robustness.py`, `run_missing_robustness.py`, `run_baselines.py`, `run_horizon.py`, `run_cqr.py`, `run_per_sensor.py`, `run_temporal_splits.py`) | each writes `results/<name>.csv` |
| `python src/stress_test.py` | `results/stress_test.csv` + console (worst-site, Winkler) |
| `python src/analyze_domain.py` | `results/accuracy_by_band.csv` + console (vs literature) |
| `python src/make_figures.py` | redraws every figure in `figures/` from the CSVs above |

Dependencies pinned in `../requirements.txt` (Python 3.14.3). Gate/parquet regeneration
(`gate_checks.py`) needs the raw PERMOS release under `data/raw/` — re-download from the DOI.
